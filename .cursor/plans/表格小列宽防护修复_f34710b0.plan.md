# 表格 Tiptap 默认列宽防护

## 为什么上一轮修复只解决了 `改.docx` 而没解决 `改2.docx`

上一轮 Fix 1 移除了 `min-width` 解析，只处理了 **一种** 产生 25px 列宽的路径：

```
Tiptap getHTML() → <col style="min-width: 25px"> → [Fix 1] 忽略 → 返回 0 → OK
```

但存在 **另一条路径** 仍然产生 25px 列宽：

1. 某些导入路径（OOXML 合并替换、docx-preview、或 `normalizeHtmlThroughDocModel` 往返）产生 `<col style="width: 25px" width="25">` 或 `<col style="width: 25px">`
2. Tiptap 加载此 HTML → 单元格存储 `colwidth: [25]`
3. `editor.getHTML()` → `<col style="width: 25px">`（CSS `width`，不是 `min-width`）
4. `htmlParser.ts` 解析 CSS `width: 25px` → `colWidths: [25, 25, ...]`
5. `buildTable` 中 `every(w > 0)` → true → DXA 模式 → 每列仅 375 twips → 极窄

Fix 1 无法拦截这条路径，因为 `width: 25px` 不是 `min-width`。

## 根本判断标准

Tiptap 的 `cellMinWidth` 默认值为 25px。任何所有列宽都 <= 25px 的表格，几乎不可能是来自真实文档的列宽（25px ≈ 0.26 英寸 ≈ 6.6mm，无法显示任何有意义的内容）。这些值一定是 Tiptap 的默认占位值，不应作为 DOCX 导出的列宽。

## 修复方案

### Fix 3: `htmlParser.ts` — 检测并丢弃 Tiptap 默认列宽

`[htmlParser.ts](collabedit-fe/src/views/training/document/utils/docModel/htmlParser.ts)` `parseTable` 函数，在解析完 `colWidths` 后增加防护：

```typescript
// 当前代码（Fix 1 后）:
const colWidths = colgroup
  ? Array.from(colgroup.querySelectorAll('col'))
      .map((col) => { ... return width || parsePxValue(colMap['width']) || 0 })
  : undefined

// 修改为:
const rawColWidths = colgroup
  ? Array.from(colgroup.querySelectorAll('col'))
      .map((col) => { ... return width || parsePxValue(colMap['width']) || 0 })
  : undefined
const CELL_MIN_WIDTH = 25
const colWidths = rawColWidths?.length && rawColWidths.some(w => w > CELL_MIN_WIDTH)
  ? rawColWidths
  : undefined
```

判断逻辑：如果**至少一个**列宽 > 25px，视为有效真实宽度；否则视为 Tiptap 默认值，丢弃为 `undefined`。

### Fix 4: `docModelToDocx.ts` — buildTable 增加相同防护

`[docModelToDocx.ts](collabedit-fe/src/views/training/document/utils/docModel/docModelToDocx.ts)` 第 472 行 `buildTable`：

```typescript
// 当前:
const hasColWidths = block.colWidths?.length && block.colWidths.every((w) => w > 0)

// 修改为:
const CELL_MIN_WIDTH = 25
const hasColWidths =
  block.colWidths?.length &&
  block.colWidths.every((w) => w > 0) &&
  block.colWidths.some((w) => w > CELL_MIN_WIDTH)
```

### Fix 5: `docModelToDocx.ts` — buildEndnoteTableXml 增加相同防护

第 891-892 行 `useColWidths` 判断增加 `some(w > 25)`：

```typescript
// 当前:
const useColWidths = table.colWidths?.length === columnCount && table.colWidths.every((w) => w > 0)

// 修改为:
const CELL_MIN_WIDTH = 25
const useColWidths =
  table.colWidths?.length === columnCount &&
  table.colWidths.every((w) => w > 0) &&
  table.colWidths.some((w) => w > CELL_MIN_WIDTH)
```

## 场景覆盖

- **所有列 `min-width: 25px`** → Fix 1 返回 0 → Fix 3 `some(>25)` false → undefined
- **所有列 `width: 25px`** → Fix 3 `some(>25)` false → undefined
- **所有列 `width: 0px`** → Fix 3 `some(>25)` false → undefined
- **真实列宽 `[120, 300]`** → Fix 3 `some(>25)` true → 保留 → DXA 模式
- **混合 `[25, 300]`** → Fix 3 `some(>25)` true → 保留 → DXA 模式（25px 列虽窄但有其他宽列）

## 回归影响

- 不影响有真实列宽的表格（至少有一列 > 25px）
- 不影响之前 `附件1.docx` 的修复（其列宽远 > 25px）
- 不影响手动调整过列宽的表格（调整后宽度通常 > 25px）
