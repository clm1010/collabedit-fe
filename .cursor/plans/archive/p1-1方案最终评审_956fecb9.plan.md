## 逐项评审

### Fix 1: imageStyle 使用 node.attrs -- 正确，核心修复

**根因确认**：[ResizableImageComponent.vue](e:/job-project/collabedit-fe/src/views/training/document/components/toolbar/extensions/ResizableImageComponent.vue) 第 249-257 行的 `imageStyle` 始终返回 `width: 'auto', height: 'auto'`，完全忽略了 `node.attrs.width/height` 和拖拽中的 `currentWidth/currentHeight`。

```249:257:e:/job-project/collabedit-fe/src/views/training/document/components/toolbar/extensions/ResizableImageComponent.vue
const imageStyle = computed(() => {
  return {
    maxWidth: `${editorMaxWidth.value}px`,
    width: 'auto',
    height: 'auto',
    display: imageError.value ? 'none' : 'block'
  }
})
```

**方案中的修复逻辑正确**：

- 拖拽中使用 `currentWidth/currentHeight` 提供实时视觉反馈
- 非拖拽时使用 `node.attrs.width/height` 显示保存的尺寸
- 无 width/height 时回退 `auto`，**不影响现有旧图片**

**无遗漏。**

---

### Fix 2: 移除 `height: auto !important` -- 正确，Fix 1 的必要前置

**确认存在**：第 674 行 `.image-container img` 中有 `height: auto !important`：

```669:677:e:/job-project/collabedit-fe/src/views/training/document/components/toolbar/extensions/ResizableImageComponent.vue
  img {
    border-radius: 4px;
    cursor: default;
    user-select: none;
    display: block !important;
    height: auto !important;
    max-height: none !important;
  }
```

**scoped CSS `!important` 优先级高于 inline style**，如果不移除，Fix 1 设置的 `height: Xpx` 会被覆盖，拖拽调整高度仍然无效。

**无遗漏。**

---

### Fix 3: 预览/导出对齐 CSS -- 正确

**根因确认**：[ResizableImage.ts](e:/job-project/collabedit-fe/src/views/training/document/components/toolbar/extensions/ResizableImage.ts) 第 107-111 行的 `renderHTML` 只输出 `data-align`，而 [TiptapEditor.vue](e:/job-project/collabedit-fe/src/views/training/document/components/TiptapEditor.vue) 的预览区域 CSS（第 1526-1530 行）没有 `data-align` 规则：

```1526:1530:e:/job-project/collabedit-fe/src/views/training/document/components/TiptapEditor.vue
  :deep(img) {
    max-width: 100%;
    height: auto;
    display: block;
  }
```

方案的双重修复策略正确：

- 在 `renderHTML` 中同时输出 `data-align` + inline `style`（兜底，不依赖外部 CSS）
- 在 TiptapEditor.vue 中添加 `img[data-align]` CSS 规则

**编辑器中的对齐不受影响**：编辑器中对齐由 `wrapperStyle`（第 212-230 行 flexbox justifyContent）控制，与 `renderHTML` 无关。

**需要补充一点**：TiptapEditor.vue 的 `.pdf-preview`（第 1610-1613 行）也有 `:deep(img)` 规则，同样需要添加 `data-align` CSS，否则 PDF 导出预览中对齐也会失效。方案中只提到了 `.html-preview`，但建议在整个组件层级添加 CSS 规则以覆盖所有预览场景。

### Fix 5: 双击图片改为预览（而非新标签页打开）

**现状**：`handleDoubleClick`（第 364-368 行）使用 `window.open(src, '_blank')` 在浏览器新标签页打开图片原始链接（base64 或 blob URL），体验差。

```364:368:e:/job-project/collabedit-fe/src/views/training/document/components/toolbar/extensions/ResizableImageComponent.vue
const handleDoubleClick = () => {
  if (props.node.attrs.src) {
    window.open(props.node.attrs.src, '_blank')
  }
}
```

**修改**：改为调用已有的 `previewImage()` 方法，复用组件内置的预览弹窗（支持缩放、拖拽、快捷键、下载）：

```typescript
const handleDoubleClick = () => {
  if (props.node.attrs.src && !imageError.value) {
    previewImage()
  }
}
```

**无副作用**：预览弹窗已完整实现（Teleport to body、ESC 关闭、+/- 缩放、滚轮缩放、拖拽平移、下载），不影响其他功能。
