# 修复图片保存后排版丢失（行内 + 块级）

## 根本原因

保存流程为：`editor.getHTML()` -> `normalizeHtmlThroughDocModel()` -> `parseHtmlToDocModel()` -> `docModelToDocx()` -> 上传 DOCX

```mermaid
flowchart LR
    A["editor.getHTML()"] -->|"data-display=inline 正确"| B["normalizeHtmlThroughDocModel"]
    B -->|"HTML->DocModel: inline 丢失"| C["DocModel"]
    C -->|"DocModel->HTML: 无 data-display"| D["损坏的 HTML"]
    D --> E["parseHtmlToDocModel"]
    E -->|"img 全部拆为独立 block"| F["DocModel"]
    F --> G["docModelToDocx"]
    G -->|"每个图片单独 Paragraph，且无对齐"| H["DOCX: 排版错乱"]
```

### 行内图片：5 个断裂点

1. [htmlParser.ts](e:\job-project\collabedit-fe\src\views\training\document\utils\docModel\htmlParser.ts) `parseParagraphWithInlineImages()` 第 241-244 行：遇到任何 `<img>` 都 `flushParagraph()` + 拆为独立 `DocImageBlock`，不检查 `data-display`
2. [htmlParser.ts](e:\job-project\collabedit-fe\src\views\training\document\utils\docModel\htmlParser.ts) `parseImage()` 第 308-342 行：不读取 `data-display` 属性
3. [types.ts](e:\job-project\collabedit-fe\src\views\training\document\utils\docModel\types.ts)：`DocRun` 无法表达行内图片，`DocImageBlock` 无 `display` 字段
4. [serializer.ts](e:\job-project\collabedit-fe\src\views\training\document\utils\docModel\serializer.ts) `serializeRun()` + `serializeBlock(image)` 第 61-176 行：不输出 `data-display`
5. [docModelToDocx.ts](e:\job-project\collabedit-fe\src\views\training\document\utils\docModel\docModelToDocx.ts) `buildImageParagraph()` 第 273-304 行：所有图片都创建独立 `Paragraph`，无行内图片概念

### 块图片：对齐丢失

1. [docModelToDocx.ts](e:\job-project\collabedit-fe\src\views\training\document\utils\docModel\docModelToDocx.ts) `buildImageParagraph()` 第 303 行：`new Paragraph({ children: [image] })` 未传入 `alignment`，导致编辑器中居中/右对齐的块图片在 DOCX 中变为左对齐
2. [serializer.ts](e:\job-project\collabedit-fe\src\views\training\document\utils\docModel\serializer.ts) 第 155-176 行：块图片序列化时不输出 `data-display="block"` 和 `style="display: block; ..."` → normalizeHtmlThroughDocModel 往返后 Tiptap 虽默认 block 不受影响，但缺少 `display: block` 和 `margin: auto` 的 CSS 样式

## 修复方案

### 1. types.ts -- 扩展类型定义

新增 `DocInlineImage` 接口，在 `DocRun` 中增加可选 `image` 字段：

```typescript
export interface DocInlineImage {
  src: string
  originSrc?: string
  alt?: string
  width?: number
  height?: number
}

export interface DocRun {
  text: string
  style?: RunStyle
  footnoteId?: number
  endnoteId?: number
  image?: DocInlineImage // 新增：行内图片
}
```

### 2. htmlParser.ts -- 正确解析行内图片

修改 `parseParagraphWithInlineImages()` 第 241-244 行，对 `data-display="inline"` 的 `<img>` 创建带 `image` 的 `DocRun`，保留在当前段落的 runs 中，不拆为独立 block：

```typescript
if (tag === 'img') {
  const display = el.getAttribute('data-display')
  if (display === 'inline') {
    // 行内图片：保留在段落 runs 中
    const rawOriginSrc = el.getAttribute('data-origin-src') || undefined
    const rawSrc = rawOriginSrc || el.getAttribute('src') || ''
    currentRuns.push({
      text: '',
      image: {
        src: cleanDataUrlWhitespace(rawSrc),
        originSrc: rawOriginSrc ? cleanDataUrlWhitespace(rawOriginSrc) : undefined,
        alt: el.getAttribute('alt') || undefined,
        width: parsePxValue(el.getAttribute('width') || undefined),
        height: parsePxValue(el.getAttribute('height') || undefined)
      }
    })
  } else {
    // 块级图片：拆为独立 block（保持现有逻辑）
    flushParagraph()
    blocks.push(parseImage(el))
  }
  return
}
```

### 3. serializer.ts -- 序列化行内图片回 HTML + 补全块图片属性

**3a. serializeRun()** 头部新增 `run.image` 处理：

```typescript
const serializeRun = (run: DocRun): string => {
  if (run.image) {
    const img = run.image
    const resolvedSrc = img.originSrc || img.src
    const attrs: string[] = [
      `src="${escapeAttr(resolvedSrc)}"`,
      'class="editor-image"',
      'data-display="inline"'
    ]
    if (img.originSrc) attrs.push(`data-origin-src="${escapeAttr(img.originSrc)}"`)
    if (img.alt) attrs.push(`alt="${escapeHtml(img.alt)}"`)
    if (img.width) attrs.push(`width="${img.width}"`)
    if (img.height) attrs.push(`height="${img.height}"`)
    attrs.push('style="display: inline-block; vertical-align: bottom;"')
    return `<img ${attrs.join(' ')} />`
  }
  // ... 现有逻辑不变
}
```

**3b. serializeBlock(image)** 补充 `data-display="block"` 和对齐 style：

### 4. docModelToDocx.ts -- 行内图片导出 + 块图片对齐修复

**4a. ParagraphChild 类型** 加入 `ImageRun`：

```typescript
type ParagraphChild = TextRun | FootnoteReferenceRun | ExternalHyperlink | ImageRun
```

**4b. 预加载行内图片缓存**（避免将整条同步调用链改为异步）：

在 `blocksToElements()` 入口处，先扫描所有 blocks 中的 `DocRun.image`，批量 `await loadImageData()`，存入 `Map` 缓存：

```typescript
const preloadInlineImages = async (
  blocks: DocBlock[]
): Promise<Map<string, { data: Uint8Array; type: 'png' | 'jpg' | 'gif' | 'bmp' }>> => {
  const cache = new Map()
  const srcs = new Set<string>()
  const collect = (blocks: DocBlock[]) => {
    blocks.forEach((block) => {
      if (block.type === 'paragraph' || block.type === 'heading') {
        block.runs.forEach((run) => {
          if (run.image) srcs.add(run.image.src)
        })
      }
      if (block.type === 'blockquote') collect(block.blocks)
      if (block.type === 'list') block.items.forEach((item) => collect(item.blocks))
    })
  }
  collect(blocks)
  await Promise.all(
    [...srcs].map(async (src) => {
      const data = await loadImageData(src)
      if (data) cache.set(src, data)
    })
  )
  return cache
}
```

**4c. mapRunToRuns()** 使用预加载缓存处理 `run.image`：

```typescript
let _inlineImageCache: Map<string, { data: Uint8Array; type: ... }> = new Map()

const mapRunToRuns = (run: DocRun): ParagraphChild[] => {
  if (run.image) {
    const cached = _inlineImageCache.get(run.image.src)
    if (!cached) return []
    let width = run.image.width || 200
    let height = run.image.height || 150
    if (width > 300) { const r = 300 / width; width = 300; height = Math.round(height * r) }
    return [new ImageRun({ data: cached.data, type: cached.type, transformation: { width, height } })]
  }
  // ... 现有逻辑不变
}
```

## 评审检查清单

### 不会影响现有功能的保证

- **块图片处理路径不变**：`parseParagraphWithInlineImages` 中 `data-display` 非 `'inline'` 的图片仍走原有 `flushParagraph() + parseImage()` 路径
- **DocImageBlock 接口不变**：块图片的类型定义未修改，所有消费 `DocImageBlock` 的代码不受影响
- **mapRunToRuns 同步性不变**：通过预加载缓存避免异步化，`createParagraph` 及所有调用方（`buildParagraph`、`buildHeading`、`buildBlockquote`、`buildList`）无需改动
- **blocksToParagraphs 不受影响**：该函数不处理 `DocImageBlock`（这是 pre-existing 行为），本次修复不改变此行为
- **Tiptap parseHTML 兼容**：`data-display` 缺失时默认 `'block'`，补充输出 `data-display` 只会增强兼容性
- **docx4jsParser.ts 不受影响**：DOCX 导入路径中不涉及 `data-display` 解析（DOCX 格式本身没有 inline image 概念，图片都是独立的 drawing 元素）
