# 修复图片节点排版与交互问题（v2 - 采纳评审建议）

## 问题根因分析

### 问题 1: 文字段落和块图片没有分离

**根因**: `ResizableImage.ts` 默认 `inline: false`，但 `TiptapEditor.vue` 第 462 行覆盖配置为 `inline: true`。图片在 ProseMirror schema 中是行内节点（`group: 'inline'`），始终存在于 `<p>` 标签内部。块图片和文字没有结构性分离。

**参考 UMO Editor**: UMO 使用两个独立节点类型。我们无需重构为双节点架构，只需在插入块图片时确保正确分段。

### 问题 2: 换行符 ↵ 多占一行

**根因**: ProseMirror 在空段落或以行内原子节点结尾的段落末尾添加 `<br class="ProseMirror-trailingBreak">`。CSS `p::after { content: '↵' }` 出现在 `<br>` 之后，被挤到下一行。

```
DOM 结构:
<p>
  <br class="ProseMirror-trailingBreak">  <- 创建一个空行
  ::after { content: '↵' }               <- 被挤到第二行
</p>
```

需分两种情况处理：

- **空段落**（trailingBreak 是唯一子元素）：隐藏 `<br>`，保留 `↵` 显示（通过 `::after`）
- **非空段落 + trailingBreak**（图片/hardBreak 后面跟 trailingBreak）：隐藏 `↵` 避免多占一行

### 问题 3: 软回车（Shift+Enter）无视觉标记

**根因**: `<br>` 是 void 元素，无法通过 CSS 伪元素添加标记。需要 ProseMirror Decoration 插件。

**参考 UMO Editor (pp5.jpg)**:

- **↵** — 段落结束标记（Enter）
- **↓** — 软回车标记（Shift+Enter）

### 问题 4: 没有拖拽手柄

**根因**: 官方 DragHandle 组件针对顶层块元素。图片是 inline 节点在 `<p>` 内部，需要图片自身的拖拽手柄。`ResizableImage.ts` 中的 `draggable: { default: true }` 只是数据属性，不是扩展级拖拽设置。

### 问题 5: 多余的蓝色边框

**根因**: 两层边框叠加：

1. `TiptapEditor.vue` 第 1737 行: `.ProseMirror-selectednode { outline: 2px solid #2563eb }`
2. `ResizableImageComponent.vue` 第 691 行: `.is-selected .image-container { outline: 2px solid #1a73e8 }`

## 修改方案

### 新建文件: [HardBreakMarker.ts](src/views/training/document/components/toolbar/extensions/HardBreakMarker.ts)

创建 TipTap Extension，通过 ProseMirror Decoration 在每个 `hardBreak` 节点位置插入 `↓` 标记。

**性能优化**（采纳评审建议）：使用 Plugin State 的 `init/apply` 模式，仅在文档变更时重建装饰集，避免每次状态更新遍历整个文档。

```typescript
import { Extension } from '@tiptap/core'
import { Plugin, PluginKey } from '@tiptap/pm/state'
import { Decoration, DecorationSet } from '@tiptap/pm/view'

const buildDecorations = (doc: any): DecorationSet => {
  const decorations: Decoration[] = []
  doc.descendants((node: any, pos: number) => {
    if (node.type.name === 'hardBreak') {
      decorations.push(
        Decoration.widget(pos, () => {
          const marker = document.createElement('span')
          marker.className = 'hard-break-marker'
          marker.textContent = '↓'
          marker.contentEditable = 'false'
          return marker
        }, { side: 0 })
      )
    }
  })
  return DecorationSet.create(doc, decorations)
}

export const HardBreakMarker = Extension.create({
  name: 'hardBreakMarker',
  addProseMirrorPlugins() {
    return [
      new Plugin({
        key: new PluginKey('hardBreakMarker'),
        state: {
          init(_, { doc }) {
            return buildDecorations(doc)
          },
          apply(tr, oldDecorations) {
            if (tr.docChanged) {
              return buildDecorations(tr.doc)
            }
            return oldDecorations.map(tr.mapping, tr.doc)
          }
        },
        props: {
          decorations(state) {
            return this.getState(state)
          }
        }
      })
    ]
  }
})
```

**CSS 修改 — ↵ 换行符问题（评审修正版）:**

采纳评审建议，分两种情况精确处理，确保空段落仍显示 ↵：

```scss
// 情况 1: 空段落（trailingBreak 是唯一子元素）
// 隐藏 <br>，让 ::after 的 ↵ 显示在同一行，避免双行问题
p > br.ProseMirror-trailingBreak:only-child {
  display: none;
}
p:has(> br.ProseMirror-trailingBreak:only-child) {
  min-height: 1.75em; // 维持段落高度（匹配 line-height）
}

// 情况 2: 非空段落 + trailingBreak（图片后/hardBreak 后跟 trailingBreak）
// 隐藏 ↵ 标记，避免 ::after 被挤到额外的行
p:has(> br.ProseMirror-trailingBreak:last-child:not(:only-child))::after {
  content: none;
}
```

效果对比：

```
修改前：
空段落:  [br 空行] + [↵ 第二行] = 2行高  ← 错误
图片段落: [图片] + [br 空行] + [↵ 第三行] = 多占行  ← 错误

修改后：
空段落:  [↵] = 1行高（br 隐藏，↵ 取代）  ← 正确
图片段落: [图片] + [br 空行] = 无 ↵  ← 正确
文字段落: [文字↵] = 正常  ← 不受影响
```

> **实施注意**：`display: none` 隐藏 trailingBreak 可能影响 ProseMirror 在空段落中的光标定位。实施后须验证：空段落中光标是否可正常显示、输入、退格、方向键移动。如有问题，回退为 `font-size: 0; line-height: 0; height: 0;` 替代方案。

### 文件 5: [docModelToDocx.ts](src/views/training/document/utils/docModel/docModelToDocx.ts) — DOCX 导出软回车修复

**问题**: `htmlParser.ts` 将 `<br>` 解析为 `{ text: '\n' }`，但 `docModelToDocx.ts` 的 `mapRunToRuns()` 和 `runToEndnoteXml()` 直接把 `\n` 作为文本传入 `TextRun`。DOCX 中段内换行必须用 `<w:br/>` 表示。

> **已确认**: `htmlToDocx.ts`（直接 HTML-to-DOCX 路径）已在第 329-330 行正确处理 `<br>` → `TextRun({ break: 1 })`，无需修改。仅 DocModel 路径需要修复。

**修复 mapRunToRuns() (第 70-115 行)**:

```typescript
const parts = (run.text || '').split('\n')
const results: ParagraphChild[] = []
parts.forEach((part, idx) => {
  const opts: any = { ...styleOptions }
  if (idx > 0) {
    opts.break = 1
  }
  opts.text = part
  results.push(new TextRun(opts))
})
return results
```

**修复 runToEndnoteXml() (第 544-570 行)**:

```typescript
const text = run.text || ''
const parts = text.split('\n')
const xmlParts = parts.map((part, idx) => {
  const escapedPart = escapeXmlText(part)
  const brTag = idx > 0 ? '<w:br/>' : ''
  return `<w:r>${rPr}${brTag}<w:t xml:space="preserve">${escapedPart}</w:t></w:r>`
})
return xmlParts.join('')
```
