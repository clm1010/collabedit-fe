# 表格斜体和列宽修复方案

## 问题 1：表格文字保存后变斜体

### 根因分析

保存链路为: `getHTML()` -> `normalizeHtmlThroughDocModel()` (2 次 parse) -> `docModelToDocx()`。

经确认编辑器中 I 按钮未激活（文字确实不是斜体），斜体是在 DOCX 导出阶段被引入的。发现两个相关 bug：

**Bug A**: `docx` 库 (v9.5.1) 的 `DefaultStylesFactory` 中，`Heading4Style` 默认包含 `italics: true`：

```17212:17217:node_modules/docx/dist/index.iife.js
          new Heading4Style(__spreadValues({
            run: {
              color: "2E74B5",
              italics: true     // <-- 这里导致所有 Heading4 段落带斜体
            }
          }, options.heading4)),
```

增强版 OOXML 导入器 `convertParagraphEnhanced` 会将表格单元格内带有 `w:pStyle` (如 Heading4 / 标题4 / 带 outlineLevel 的样式) 的段落输出为 `<h4>`，Tiptap 显示时不带斜体，但 `buildHeading()` 导出时使用 `HeadingLevel.HEADING_4`，继承了库默认的 `italics: true`。

**Bug B**: `[mapRunToRuns](src/views/training/document/utils/docModel/docModelToDocx.ts)` 只在 `style.italic` 为 true 时设置 `styleOptions.italics = true`，但当 `style.italic` 为 falsy 时 **不会** 设置 `italics: false`。在 `docx` 库中，`RunProperties` 只在 `options.italics !== undefined` 时才输出 `<w:i>` 元素，所以不设置等于"继承父样式"。如果段落样式(如 Heading4)含斜体，所有子 run 都会继承。

### 修复方案

**Fix A**: 在 `docModelToDocx.ts` 的 `Document` 构造函数中，通过 `styles` 选项覆盖 Heading4 默认样式，移除 `italics: true`：

```typescript
const doc = new Document({
  // ...existing options...
  styles: {
    default: {
      heading4: {
        run: {
          italics: false
        }
      }
    }
  },
  // ...
})
```

**Fix B**: 在 `mapRunToRuns` 中，显式设置 `italics: false`：

```typescript
// 原代码:
if (style.italic) styleOptions.italics = true

// 修改为:
styleOptions.italics = !!style.italic
```

同理对 `bold` 也做防御性处理:

```typescript
styleOptions.bold = !!style.bold
```

## 问题 2：表格列宽保存不一致

### 根因分析

`[buildTable](src/views/training/document/utils/docModel/docModelToDocx.ts)` 第 502-506 行:

```typescript
return new Table({
  rows,
  width: { size: 100, type: WidthType.PERCENTAGE },  // 表宽固定 100%
  layout: TableLayoutType.FIXED
})
```

各列宽通过 `pxToTwip(colWidth)` 转换为 DXA 值设置在 `TableCell.width` 上。但表宽为 `100% PERCENTAGE` 意味着 Word/WPS 会按页面内容宽度（约 9360 twips）重新分配各列宽。当编辑器中各列宽之和（如 ~650px = ~9750 twips）与页面宽度不一致时，Word 会按比例缩放所有列宽，导致比例改变。

转换公式：

- 导入: `dxaToPx = dxa * 96 / 1440`（即 `dxa / 15`）
- 导出: `pxToTwip = px * 15`
- 二者互逆，取整误差很小

### 修复方案

当 `colWidths` 存在且有效时，使用列宽之和作为绝对表宽（`WidthType.DXA`），而非 `100%`。这样 Word/WPS 不会重新分配列宽:

```typescript
const buildTable = (block: DocTableBlock): Table => {
  // ...existing row building code...

  let tableWidth: { size: number; type: typeof WidthType.PERCENTAGE | typeof WidthType.DXA }
  if (block.colWidths?.length && block.colWidths.some(w => w > 0)) {
    const totalTwips = block.colWidths.reduce((sum, w) => sum + pxToTwip(w || 0), 0)
    tableWidth = { size: totalTwips, type: WidthType.DXA }
  } else {
    tableWidth = { size: 100, type: WidthType.PERCENTAGE }
  }

  return new Table({
    rows,
    width: tableWidth,
    layout: TableLayoutType.FIXED
  })
}
```

同时需要在 `buildEndnoteTableXml` 中做同样的修改：当有 `colWidths` 时，`<w:tblW>` 使用 DXA 绝对值而非 `auto`。
