# 表格斜体和列宽修复方案（评审修订版）

修改文件：[docModelToDocx.ts](src/views/training/document/utils/docModel/docModelToDocx.ts)

---

## 问题 1：表格文字保存后变斜体

### 根因

`docx` 库 Heading4 默认样式含 `italics: true`（[index.iife.js:17215](node_modules/docx/dist/index.iife.js)），当 OOXML 导入器将表格内的段落解析为 `<h4>` 标签时，Tiptap 不显示斜体，但 `buildHeading()` 导出时继承了库的 Heading4 默认斜体。同时 `mapRunToRuns`（行 106）只在 `style.italic === true` 时设置 `italics: true`，不设值时 `docx` 库不输出 `<w:i>` 元素，导致 run 继承段落样式的斜体。

### Fix A: 覆盖 Heading4 默认样式

在 [docModelToDocx.ts:1132](src/views/training/document/utils/docModel/docModelToDocx.ts) 的 `new Document({...})` 中添加 `styles` 选项：

```typescript
const doc = new Document({
  // ... existing options ...
  styles: {
    default: {
      heading4: {
        run: { italics: false }
      }
    }
  }
  // ... sections, numbering 等保持不变 ...
})
```

### Fix B: mapRunToRuns 中显式设 italics: false

将 [docModelToDocx.ts:106](src/views/training/document/utils/docModel/docModelToDocx.ts)：

```typescript
// 原代码：
if (style.italic) styleOptions.italics = true

// 改为：
styleOptions.italics = !!style.italic
```

**重要**：仅对 `italics` 做此处理。`bold` 保持 `if (style.bold) styleOptions.bold = true` 不变。原因：H1-H6 均未在 `docx` 库中定义 bold，标题的粗体来自 Word 内置样式继承。若将 bold 也设为 `false`，会导致标题文字丢失粗体（Tiptap `getHTML()` 输出 `<h2>text</h2>` 不含 `<strong>` 标签，run 的 `style.bold` 为 undefined）。

## 问题 2：表格列宽保存不一致

### 根因

`buildTable`（行 502-506）将表宽固定为 `{ size: 100, type: WidthType.PERCENTAGE }`，Word/WPS 会按页面内容宽度（~9360 twips）重新按比例分配各列宽。当编辑器中各列宽之和与页面宽度不一致时，列宽比例会被改变。

### Fix C: buildTable 中使用 DXA 绝对表宽

当所有列都有有效宽度时，使用列宽总和作为 DXA 绝对表宽：

```typescript
let tableWidth: { size: number; type: (typeof WidthType)[keyof typeof WidthType] }
if (block.colWidths?.length && block.colWidths.every((w) => w > 0)) {
  const totalTwips = block.colWidths.reduce((sum, w) => sum + pxToTwip(w), 0)
  tableWidth = { size: totalTwips, type: WidthType.DXA }
} else {
  tableWidth = { size: 100, type: WidthType.PERCENTAGE }
}

return new Table({
  rows,
  width: tableWidth,
  layout: TableLayoutType.FIXED
})
```

关键：使用 `every(w => w > 0)` 而非 `some`。若有任意列宽为 0（如导入时未解析到），退回 100% 百分比模式，避免产生不完整的表格。

### Fix D: buildEndnoteTableXml 同步修改列宽

当前代码（行 859-866）将 9000 twips 等分：

```typescript
const gridWidth = Math.max(1, Math.round(9000 / columnCount))
const grid = Array.from({ length: columnCount })
  .map(() => `<w:gridCol w:w="${gridWidth}"/>`)
  .join('')
```

修改为使用 `table.colWidths`（如果可用）：

```typescript
let gridColsXml: string
let tblWXml: string
if (table.colWidths?.length && table.colWidths.every((w) => w > 0)) {
  const colTwips = table.colWidths.map((w) => pxToTwip(w))
  gridColsXml = colTwips.map((tw) => `<w:gridCol w:w="${tw}"/>`).join('')
  const totalTwips = colTwips.reduce((a, b) => a + b, 0)
  tblWXml = `<w:tblW w:w="${totalTwips}" w:type="dxa"/>`
} else {
  const gridWidth = Math.max(1, Math.round(9000 / columnCount))
  gridColsXml = Array.from({ length: columnCount })
    .map(() => `<w:gridCol w:w="${gridWidth}"/>`)
    .join('')
  tblWXml = '<w:tblW w:w="0" w:type="auto"/>'
}
```

同时更新 cell 宽度（行 921）使用实际 colWidths 而非等分值：

```typescript
// 计算单元格宽度时使用 colWidths
const cellWidthTwips =
  table.colWidths?.length && table.colWidths.every((w) => w > 0)
    ? table.colWidths.slice(colIndex, colIndex + colspan).reduce((s, w) => s + pxToTwip(w), 0)
    : gridWidth * colspan
tcPrParts.push(`<w:tcW w:w="${cellWidthTwips}" w:type="dxa"/>`)
```
