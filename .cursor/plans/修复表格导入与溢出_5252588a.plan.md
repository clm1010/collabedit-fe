# 修复 Word 文档表格全链路问题（导入/保存/导出/显示）

## 全链路数据流

```
导入: DOCX → wordParser.ooxml.ts → HTML → Tiptap 编辑器
保存: editor.getHTML() → normalizeHtmlThroughDocModel (htmlParser→serializer 往返) → parseHtmlToDocModel → docModelToDocx → DOCX
导出: 同保存管线 → downloadBlob
获取: 后端返回 DOCX → 走导入管线
```

每个环节的表格处理都经过了检查，以下按**层级**组织所有问题和修复。

---

## 第一层：OOXML 导入解析（影响：导入显示）

**文件**: `[wordParser.ooxml.ts](e:\job-project\collabedit-fe\src\views\training\document\utils\wordParser.ooxml.ts)`

### 问题 A1: 合并单元格完全不支持（最严重 - 导致内容"消失"）

`convertTableCellEnhanced` 遍历 `w:tcPr` 时只读取 `w:vAlign` 和 `w:shd`，完全忽略了：

- `**w:gridSpan` — 水平合并，应转为 `colspan="N"`
- `**w:vMerge` — 垂直合并，`val="restart"` 为合并起点（应计算 `rowspan`），无 val 或 `val="continue"` 为被合并行（应跳过该单元格）

后果：合并单元格被渲染为多个独立单元格 → 列数错乱 → 表格结构崩塌 → 内容看似"消失"。

### 问题 A2: 列宽信息完全丢失

`convertTableEnhanced` 只检查 `item['w:tr']`，完全忽略了 `w:tblGrid`（列网格定义，包含 `w:gridCol @_w:w` 列宽值）和 `w:tcW`（单元格宽度）。所有列均匀分布，无法还原原文档列宽。

### 问题 A3: 单元格内段落标签被暴力移除

```typescript
// convertTableCellEnhanced 第 1892 行
const innerContent = paraContent.replace(/<\/?p[^>]*>/g, '')
if (innerContent) content += innerContent + ' '
```

这行代码把 `<p style="text-align:center">` 连同段落样式一起移除，且多段落用空格拼接丢失分隔。**Tiptap 要求 `<td>` 内必须包含 `<p>` 等块级元素**，直接放裸文本会导致解析失败。

### 修复方案

`**convertTableEnhanced` 改造：

1. 预扫描 `w:tblGrid` → 提取列宽数组 `gridCols`
2. 生成 `<colgroup><col style="width:Npx" width="N">` 输出列宽（同时输出 `width` 属性以兼容 Tiptap 的 `colwidth` parseHTML 回退逻辑）
3. 预扫描所有行的 `w:vMerge` → 构建 `vMergeMap[colIndex][rowIndex]` 映射表，计算每个 `restart` 单元格的实际 rowspan
4. 输出时对 `vMerge continue` 单元格跳过（不生成 `<td>`）

`**convertTableCellEnhanced` 改造：

1. 读取 `w:gridSpan` → 输出 `colspan="N"` + `colwidth` 属性（逗号分隔的列宽值）
2. 读取 `w:vMerge` → 返回 merge 状态（由 `convertTableEnhanced` 决定是否跳过）
3. 读取 `w:tcW` → 输出单元格宽度
4. **保留 `<p>` 标签**（不再用正则移除），直接拼接 `convertParagraphEnhanced` 的输出

**同步修复 `convertTableToHtml`（非增强版）的同类问题。**

## 第二层：DocModel 中间模型（影响：导入 DocModel 路径 + 保存/导出管线）

保存管线的核心步骤 `normalizeHtmlThroughDocModel` 做了 `HTML → DocModel → HTML` 往返规范化。表格在此过程中的问题会同时影响保存和导出。

### 2.1 types.ts — 模型缺少单元格样式字段

**文件**: `[docModel/types.ts](e:\job-project\collabedit-fe\src\views\training\document\utils\docModel\types.ts)`

**问题 B1:** `DocTableCell` 只有 `blocks/colspan/rowspan`，缺少 `backgroundColor`、`textAlign` 字段。

**后果：** 用户在编辑器中设置单元格背景色/对齐后保存，`normalizeHtmlThroughDocModel` 往返时这些样式被丢弃 → 导出的 DOCX 丢失单元格样式 → 重新打开后样式消失。

**修复：**

```typescript
export interface DocTableCell {
  blocks: DocBlock[]
  colspan?: number
  rowspan?: number
  backgroundColor?: string // 新增
  textAlign?: string // 新增
}
```

### 2.2 htmlParser.ts — 两个问题

**文件**: `[docModel/htmlParser.ts](e:\job-project\collabedit-fe\src\views\training\document\utils\docModel\htmlParser.ts)`

**问题 B2: `querySelectorAll('tr')` 匹配嵌套表格行**

第 399 行 `element.querySelectorAll('tr')` 会匹配所有后代 `<tr>`，包括嵌套表格的。外层 `parseTable` 会错误收集内层行 → 行重复 + 结构错乱。

此问题影响**两条路径**：

- **导入**：DocModel 解析路径
- **保存/导出**：`normalizeHtmlThroughDocModel` 往返中 `parseHtmlToDocModel` 调用

**修复：**

```typescript
const trNodes = Array.from(
  element.querySelectorAll(
    ':scope > tr, :scope > thead > tr, :scope > tbody > tr, :scope > tfoot > tr'
  )
)
```

**问题 B3: parseTable 不读取单元格样式和 colwidth**

`parseTable` 对 `<td>` 只读取 `colspan/rowspan`，不读取 `style` 中的 `background-color`、`text-align`，也不读取 Tiptap 输出的 `colwidth` 属性。

**修复：** 在 `parseTable` 中增加对 `td` 的样式和 `colwidth` 属性读取，存入 `DocTableCell` 的新字段。

### 2.3 serializer.ts — 四个问题

**文件**: `[docModel/serializer.ts](e:\job-project\collabedit-fe\src\views\training\document\utils\docModel\serializer.ts)`

| 问题 | 现状 | 影响 | 修复 |
| --- | --- | --- | --- |
| **B4: 空单元格无子元素** | 输出 `<td></td>` | Tiptap 要求 `<td>` 至少含一个 `<p>` | 改为 `<td><p></p></td>` |
| **B5: col 只用 min-width style** | `<col style="min-width:Npx">` | Tiptap 的 colwidth parseHTML 回退查 `col[width]` 属性，找不到 | 同时输出 `width` 属性：`<col style="width:Npx" width="N">` |
| **B6: 无 tbody 包裹** | `<table><tr>...</tr></table>` | Tiptap renderHTML 输出 `<tbody>`，不一致 | 行用 `<tbody>` 包裹 |
| **B7: 不输出单元格样式** | `<td colspan rowspan>` | normalize 往返丢失 backgroundColor/textAlign | 输出到 td 的 style 属性 |

### 2.4 docx4jsParser.ts — tbody/thead 包装

**文件**: `[docModel/docx4jsParser.ts](e:\job-project\collabedit-fe\src\views\training\document\utils\docModel\docx4jsParser.ts)`

**问题 B8:** `parseTableFromTree` 只检查直接子节点是否为 `tr`，不处理 `tbody/thead/tfoot` 包装。如果 docx4js 输出 `table > tbody > tr` 结构，整个表格内容为空。另外，空行（`cells` 数组为空）也未过滤。

**修复：** 如果子节点 type 是 `tbody/thead/tfoot`，递归遍历其 children 查找 `tr`。过滤空行。

## 第三层：DOCX 导出（影响：保存、导出 Word）

**文件**: `[docModel/docModelToDocx.ts](e:\job-project\collabedit-fe\src\views\training\document\utils\docModel\docModelToDocx.ts)`

**问题 C1:** `buildTable`（主体表格导出函数）不支持单元格背景色。对比 `buildEndnoteTableXml`（尾注表格导出，手工拼 XML）已经实现了单元格背景色（`w:shd`）支持，但主体版本遗漏了。

```460:487:e:\job-project\collabedit-fe\src\views\training\document\utils\docModel\docModelToDocx.ts
const buildTable = (block: DocTableBlock): Table => {
  // ... 当前没有 shading/borders 设置
  return new TableCell({
    children: ...,
    columnSpan: cell.colspan,
    rowSpan: cell.rowspan,
    width: cellWidth ? { size: pxToTwip(cellWidth), type: WidthType.DXA } : undefined
    // 缺少 shading
  })
}
```

**修复：** 从 `DocTableCell.backgroundColor` 读取，设置 `TableCell.shading`：

```typescript
shading: cell.backgroundColor
  ? { type: ShadingType.CLEAR, fill: cell.backgroundColor.replace('#', '') }
  : undefined
```

## 第四层：编辑器渲染 CSS（影响：编辑器显示、预览）

**文件**: `[TiptapEditor.vue](e:\job-project\collabedit-fe\src\views\training\document\components\TiptapEditor.vue)`

### 问题 D1: 缺少 `.tableWrapper` 样式

Tiptap `Table.configure({ resizable: true })` 通过 `TableView` NodeView 始终在 `<table>` 外层生成 `<div class="tableWrapper">`（参考 [Tiptap Table 源码](https://github.com/ueberdosis/tiptap/blob/main/packages/extension-table/src/table/TableView.ts#L73-L101)）。但项目中**完全没有为此容器写样式**。

### 问题 D2: `table { overflow: hidden }` 裁切内容

A4 页面可用宽度约 554px（794px - 120px2 padding），Word 文档的表格宽度经常超过此值。`overflow: hidden` 直接裁切掉超宽部分。

### 修复：

```css
/* .tiptap 内部 */
.tableWrapper {
  overflow-x: auto;
  max-width: 100%;
  margin: 1em 0;
}

table {
  border-collapse: collapse;
  width: 100%;
  margin: 0; /* margin 移到 .tableWrapper */
  /* 移除 overflow: hidden */
  border-radius: 8px;
  border: 1px solid #e5e7eb;
}
```

同时为 HTML 预览区域 (`.html-preview-content`) 和 PDF 预览区域 (`.pdf-preview-container`) 添加 `.tableWrapper` 的溢出滚动支持以及 table 不设 `overflow: hidden` 的样式。

## 风险评估

| 修改 | 风险等级 | 理由 |
| --- | --- | --- |
| OOXML 表格解析增强 | **低** | 纯新增逻辑，不修改已有解析分支 |
| DocTableCell 新增字段 | **低** | 可选字段，向后兼容 |
| htmlParser :scope 选择器 | **低** | 对无嵌套表格的行为完全一致 |
| htmlParser 读取单元格样式 | **低** | 新增属性读取，不影响已有字段 |
| serializer 输出改进 | **低** | 空单元格加 `<p>` 符合 Tiptap 规范；新增属性输出不影响解析 |
| docx4jsParser tbody 透传 | **低** | 只在子节点非 tr 时增加透传层 |
| buildTable 背景色 | **低** | 新增可选 shading 属性，无值时不影响 |
| CSS overflow 修改 | **低** | `.tableWrapper` 是新增样式；移除 `overflow: hidden` 对正常宽度表格无视觉影响 |

所有修改都是**向后兼容的增量改进**，不删除/不修改任何现有逻辑分支，只在原有基础上补充缺失的处理。
